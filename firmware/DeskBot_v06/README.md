# DeskBot v06 — жесты, часы и погода

Версия основана на неизменённом snapshot `DeskBot_v05` и сохраняет его state
machine, реакции присутствия и движения, OLED-анимации, фразы и звуковые
варианты. Новое в v06: опциональный APDS-9960, экраны реальных часов и погоды,
плавные переходы между экранами и runtime-включение/выключение звука жестами.

## APDS-9960 и общая I²C-шина

Все пять устройств работают на одной шине: SDA GPIO8, SCL GPIO9, 100 kHz.

| Устройство | Адрес |
|---|---:|
| BH1750 | `0x23` |
| VL53L0X | `0x29` |
| APDS-9960 | `0x39` |
| OLED SSD1306 | `0x3C` |
| LSM6DS3 | `0x6B` |

Подключите `VIN` APDS-9960 к совместимому с конкретным модулем питанию, `GND`
к общей земле, `SDA` к GPIO8 и `SCL` к GPIO9. Вывод `INT` не используется:
драйвер работает опросом.

`GestureSensor` — локальный адаптер v06. Он использует уже запущенный `Wire` и
не вызывает `Wire.begin()` повторно. Допускаются только ID `0xAB` (штатный) и
проверенный на стенде ID `0xA8`; проверка ID не отключена. Глобальную библиотеку
`Arduino_APDS9960` патчить не требуется. Если APDS отсутствует или имеет другой
ID, выводится `APDS-9960 NOT FOUND`, после чего все функции v05 продолжают
работать.

## Физические жесты

Плата на проверенном стенде перевёрнута по обеим осям. Инверсия локализована в
`GestureSensor`, поэтому остальная прошивка получает физические направления:

| Физический жест | Значение библиотеки | Действие |
|---|---|---|
| RIGHT | LEFT | `Face → Clock → Weather` |
| LEFT | RIGHT | `Weather → Clock → Face` |
| UP | DOWN | включить звук |
| DOWN | UP | выключить звук |

Опрос считывает не более одного FIFO-блока за проход `loop()` и не использует
runtime-`delay()`.

## Face, Clock и Weather

`DisplayMode` не входит в `RobotState`. В режимах `Clock` и `Weather` state machine,
`BoredomBehavior`, ToF, BH1750 и IMU продолжают обновляться, но face renderer не
вызывается. Поэтому невидимые смены реплик не запускают звук, а при возвращении
не воспроизводится очередь пропущенных реакций.

Часы показывают системное время ESP32 в формате `HH:MM`. После подключения к
Wi-Fi `TimeService` один раз запускает SNTP через `configTzTime()`, а дальнейший
ход времени обеспечивает системный clock ESP32 — NTP не запрашивается при
перерисовке OLED. Часовой пояс задан в `Config.h` строкой `MSK-3`: это московское
время UTC+3 без DST (в POSIX TZ знак смещения обратный).

Двоеточие между часами и минутами мигает с секундным тактом. Под временем
выводятся день недели и дата без года, например `ПН, 5 ОКТЯБРЯ`.
Названия всех месяцев заданы явно по-русски в родительном падеже и не зависят от
locale. Для `HH:MM` используется `u8g2_font_logisoso32_tf`, для русской даты —
`u8g2_font_6x13_t_cyrillic` с выводом через `drawUTF8()`.

До успешной синхронизации экран Clock показывает `--:--` и `НЕТ ВРЕМЕНИ`.
Clock перерисовывается при входе, получении времени или изменении секунды/даты;
существующий `DISPLAY_INTERVAL_MS` для анимаций Face не менялся.

## Настройка Wi-Fi и координат

Скопируйте `Secrets.example.h` в `Secrets.h` и замените значения:

```cpp
#pragma once

constexpr char WIFI_SSID[] = "YOUR_WIFI_SSID";
constexpr char WIFI_PASSWORD[] = "YOUR_WIFI_PASSWORD";

// Укажите координаты места, погоду для которого нужно показывать.
constexpr float WEATHER_LATITUDE = 0.0F;
constexpr float WEATHER_LONGITUDE = 0.0F;
```

`Secrets.h` добавлен в корневой `.gitignore` и не должен попадать в Git.
Подключение и ожидание NTP неблокирующие. При недоступном Wi-Fi или NTP робот,
датчики, жесты, Face и SoundSystem продолжают работать; повторная попытка
выполняется через интервал из `Config.h`, а не в каждом проходе `loop()`.

## Runtime mute

`config::AUDIO_ENABLED` остаётся глобальным compile-time переключателем
аудиооборудования. Если он `true`, звук при запуске разрешён. Жест DOWN вызывает
`SoundSystem::setEnabled(false)`: новые запросы отклоняются, pending-запрос
удаляется, текущее воспроизведение прерывается и DMA очищается. I2S0 и постоянная
FreeRTOS audio task при этом остаются живыми. Жест UP мгновенно разрешает новые
воспроизведения. Повторные UP/DOWN безопасны и ничего не переинициализируют.

## Сборка и проверка

Откройте `DeskBot_v06.ino`, установите U8g2, Adafruit VL53L0X, BH1750 и
SparkFun LSM6DS3, затем выберите ESP32-S3. Внешняя `Arduino_APDS9960` для v06 не
нужна. Для проверенного стенда выберите Flash Size `16MB`, Partition Scheme
`16M Flash (3MB APP/9.9MB FATFS)` и OPI PSRAM. Wi-Fi увеличивает размер образа,
поэтому стандартного раздела приложения 1,2 MB недостаточно. Перед сборкой
создайте локальный `Secrets.h`, как описано выше. Serial Monitor работает на
115200 бод.

После загрузки проверьте:

1. Стартовый лог APDS содержит адрес `0x39` и ID `0xA8`/`0xAB`.
2. RIGHT последовательно открывает часы и погоду, LEFT возвращает к часам и лицу
   без изменения `RobotState`.
3. В Clock и Weather датчики и поведение продолжают обновляться, скрытые реплики
   не звучат.
4. DOWN сразу обрывает текущий звук и запрещает новые; повторный DOWN безопасен.
5. UP возвращает звук без перезапуска I2S; повторный UP безопасен.
6. При отключённом APDS робот загружается и работает как v05.
7. Все четыре направления стабильно распознаются в физической ориентации.
8. При доступном Wi-Fi Clock показывает московское время `HH:MM` и русскую дату.
9. Без Wi-Fi/NTP Clock показывает `--:--` / `НЕТ ВРЕМЕНИ`, а робот не блокируется.

Ожидаемые строки для жестов:

```text
GESTURE: RIGHT -> CLOCK
GESTURE: RIGHT -> WEATHER
GESTURE: LEFT -> CLOCK
GESTURE: LEFT -> FACE
GESTURE: UP -> SOUND ON
GESTURE: DOWN -> SOUND OFF
```

## Экран погоды

Третий режим открывается жестом RIGHT по цепочке `Face → Clock → Weather`;
жест LEFT проходит те же режимы в обратном порядке. Режим дисплея не входит в
`RobotState`, поэтому датчики, поведение, сон, пробуждение и звук продолжают
работать, пока на OLED показана погода.

Смена экранов использует неблокирующий горизонтальный слайд длительностью
300 мс. Оба кадра OLED хранятся в RAM; во время перехода продолжаются опрос
датчиков и жестов, обновление поведения и воспроизведение звука.

`WeatherService` получает текущие условия с wttr.in в отдельной задаче
FreeRTOS. Координаты хранятся в исключённом из Git `Secrets.h`; интервал
обновления 15 минут, повтор через 60 секунд после ошибки и сетевые тайм-ауты
задаются в `Config.h`. Основной `loop()` только запускает запрос и принимает
готовый результат, не ожидая сеть. После ошибки последние успешные данные
остаются на экране с индикатором `!`. Используется компактный текстовый ответ,
а не JSON.

Сначала выполняется HTTPS-запрос. Если TLS недоступен в текущей сети,
`WEATHER_ALLOW_HTTP_FALLBACK` разрешает повтор по незашифрованному HTTP. В этом
случае координаты передаются без защиты, а Serial явно сообщает об
использовании fallback. Чтобы запретить такую передачу, установите параметр в
`false`.

Ожидаемые диагностические строки навигации:

```text
GESTURE: RIGHT -> CLOCK
GESTURE: RIGHT -> WEATHER
GESTURE: LEFT -> CLOCK
GESTURE: LEFT -> FACE
```
