# DeskBot v05 — звуковые реакции

Версия сохраняет поведение и анимации DeskBot v04 и добавляет электронный
язык через I²S-усилитель MAX98357A и динамик 4 Ω / 3 W.

## Оборудование и подключение

| MAX98357A | DeskBot |
|---|---|
| VIN | 5V / VIN |
| GND | GND |
| SD | 3.3V |
| DIN | GPIO18 |
| BCLK | GPIO16 |
| LRC / WS | GPIO17 |
| GAIN | не подключён |

Динамик подключается к `SPK+` и `SPK-`. `SPK-` — выход усилителя, а не земля:
не соединяйте его с GND.

Усилитель использует интерфейс `i2s_0`. Перед сборкой проверьте распиновку на
конкретной плате ESP32-S3.

Остальное оборудование не изменилось: ESP32-S3, SSD1306 128×64, VL53L0X,
BH1750 и LSM6DS3 на общей шине I²C (SDA GPIO8, SCL GPIO9).

## Звуковой набор

В прошивку встроены 18 mono PCM16-сэмплов с частотой 22050 Гц. Mono-сэмпл
дублируется в левый и правый каналы I²S-кадра.

Для `Waiting` доступны 2 звука, для `Bored` — 3, для `Content` — 3 новых звука,
полностью заменивших прежний. Остальным озвучиваемым состояниям назначено по
одному каноническому звуку. `Sleep` намеренно остаётся беззвучным. Для каждого
состояния последний вариант запоминается и не повторяется два раза подряд.

Звук запускается не в обработчике датчика, а сразу после вывода новой реплики
на OLED. Поэтому реплика и звук относятся к одному и тому же видимому
состоянию. Периодические новые реплики `Waiting`, `Content` и `Bored` также
запускают новый вариант соответствующего звука после перехода через `...`.

## Редактирование реплик

Все экранные реплики находятся в `Phrases.h` и сгруппированы по состояниям в
массивах `CURIOUS`, `WAITING`, `BORED`, `OFFENDED`, `RECONCILING`, `HAPPY`,
`CONTENT`, `DROWSY`, `SLEEP`, `WAKE`, `SURPRISED`, `PICKED_UP`, `DIZZY` и
`UPSIDE_DOWN`.

Количество вариантов вычисляется из размера массива автоматически. Поэтому в
массивах случайных реплик можно добавлять, удалять и переставлять строки без
изменения `Display.cpp`. В строках `CONTENT_DURATION` и `BORED_DURATION` нужно
сохранять спецификатор `%lu`: вместо него подставляется количество минут.

## Логика состояний

При включении DeskBot показывает пробуждение и затем коротко оценивает
обстановку в `Curious`:

- человек уже рядом: `Wake → Curious → Happy → Content`;
- никого нет: `Wake → Curious → Bored`.

После выхода из `Sleep` или раннего выхода из `Drowsy` запускается тот же
сценарий, что и при включении: сначала `Wake`, затем новое определение
присутствия в `Curious` и переход в `Happy → Content` либо `Bored`.
Незавершённые реакции движения перед этим сбрасываются.

После подтверждённого ухода робот сразу переходит в `Waiting`. Через
`BOREDOM_BORED_MS` ожидание сменяется состоянием `Bored`:

- быстрый возврат из `Waiting`: `Curious → Happy → Content`;
- возврат после достижения `Bored`:
  `Curious → Offended → Reconciling → Content`.

Пока активно `Waiting`, реплики из массива `WAITING` меняются каждые 2,5–3,5
секунды без немедленного повтора. Каждая новая реплика синхронно запускает звук
состояния `Waiting`.

`Curious` перед эмоциональной реакцией длится `CURIOUS_REACTION_MS`. Если
человек уходит во время `Curious`, `Happy`, `Offended`, `Reconciling` или
`Content`, новый подтверждённый уход снова переводит робота в `Waiting`.

### Поднятие и встряхивание

`PickedUp` теперь сохраняется всё время, пока робот находится в руках, а не
заканчивается по таймеру. На это время опрос ToF и социальные таймеры
приостанавливаются, чтобы поднятие не выглядело как уход человека.

- мягко подняли и поставили:
  `PickedUp → Surprised → Curious → Content`;
- встряхнули в руках:
  `PickedUp → Dizzy → PickedUp`, а после постановки —
  `Offended → Reconciling → Content`;
- встряхнули без предварительно распознанного поднятия:
  `Dizzy → Offended → Reconciling → Content`.

После постановки ToF получает `PUT_DOWN_SETTLE_MS` на стабилизацию. Если затем
датчик подтверждает, что человек ушёл, обычная логика присутствия переводит
робота в `Waiting`, не дожидаясь завершения всей эмоциональной цепочки.

## Архитектура воспроизведения

`SoundSystem` — единственный владелец I²S0. Постоянная FreeRTOS-задача читает
`const PROGMEM` PCM напрямую из flash, масштабирует его в небольшой stereo/DMA
буфер и пишет блоками по 128 mono-сэмплов. Основной `loop()` при этом продолжает
обслуживать дисплей, ToF, датчик света, IMU и state machine.

Одновременно играет не более одного звука. Одноэлементная FreeRTOS-очередь не
накапливает устаревшие реплики: хранится только один актуальный запрос. Если на
экране появилась следующая реплика, её звук прерывает предыдущий на границе
короткого DMA-блока.

## Настройка и запуск

Параметры звука находятся в блоке `AUDIO` файла `Config.h`:

- `AUDIO_VOLUME = 0.50F` — громкость; меняйте её без редактирования PCM;
- `AUDIO_ENABLED = false` — полное программное отключение I²S и реакций;
- GPIO, частота, размер DMA-буфера и параметры задачи задаются там же.

1. Откройте `DeskBot_v05.ino` в Arduino IDE.
2. Установите U8g2, Adafruit VL53L0X, BH1750 и SparkFun LSM6DS3.
3. Выберите ESP32-S3; для проверенного стенда используются Flash 16 MB и OPI
   PSRAM (аудиосистема сама по себе PSRAM не требует).
4. Соберите и загрузите скетч, затем откройте Serial Monitor на 115200 бод.

При успешном старте появляются строки:

```text
AUDIO: MAX98357A legacy I2S path initialized
AUDIO: 22050 Hz / PCM16 / 13 states / 18 clips / volume=0.50
```
